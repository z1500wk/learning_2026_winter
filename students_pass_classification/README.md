# Student Pass Classification（学生是否通过分类实验）

本文件夹记录了一个基于**小样本 CSV 数据**的机器学习学习实验，  
重点不在于追求模型分数，而在于理解：

- 特征是否真的有用
- 高准确率是否可信
- 如何在小数据场景下识别 **数据泄漏（data leakage）**

这是一个**偏实验思维**的学习过程，而不是完整项目。

---

## 一、数据集说明（v1）

### 数据来源
手动构造的小型 CSV 数据集，用于模拟“学生是否通过考试”。

### 基本信息
- 样本数：12
- 特征：
  - `age`：年龄
  - `hours_study`：学习时长
  - `practice_tests`：练习题数量
- 标签：
  - `passed`（0 / 1）

---

## 二、最初实验目标（v1）

最初的目标是：
- 熟悉 sklearn 的基本分类流程
- 对比不同模型在小数据集上的表现
- 理解 baseline 的意义

尝试过的模型包括：
- DummyClassifier（baseline）
- Logistic Regression
- KNN

---

## 三、关键发现：高分数在小数据下并不一定可信

在 v1 数据集上，出现了以下现象：

- 单一特征（如 `practice_tests`、`hours_study`）
- 在某些划分或交叉验证中
- 可以达到 **1.0 的准确率**

这引发了一个关键问题：

> 这是模型真的学到了规律，  
> 还是数据本身在“泄漏答案”？

---

## 四、训练集内打乱：用于识别数据泄漏的 sanity check

为了判断高分是否来自“作弊”，进行了如下实验：

### 实验方法
- 使用 `train_test_split` 划分训练集和测试集
- **只在训练集内** 随机打乱某一个特征
- 测试集保持不变
- 重新训练并评估模型

### 观察结果（v1）
- 原始情况下：准确率可达 1.0
- 训练集内打乱后：准确率迅速下降（接近随机猜测）

### 结论
这说明：
- 某些特征在 v1 数据中几乎直接决定了标签
- 高准确率并非模型泛化能力，而是**特征与标签强绑定**
- 属于典型的“答案代理 / 数据泄漏”现象

---

## 五、改进数据：构造更接近真实世界的数据（v2）

为了避免“单一特征直接决定标签”的问题，构造了第二版数据集。

### v2 数据特点
- 标签由多个特征 **加权 + 随机噪声** 共同决定
- 不存在任何一个特征可以 100% 决定结果
- 更接近真实世界中的不确定性

生成脚本：
- `make_students_v2.py`

生成文件：
- `students_pass_v2.csv`

---

## 六、v2 数据下的特征行为变化

在 v2 数据集上观察到：

- 单一特征（如 `hours_study`）仍然能显著提升准确率
- 但准确率不再是 1.0，而是一个“较高但不完美”的数值
- 在训练集内打乱特征后：
  - 性能可能下降
  - 但不会像 v1 那样立即崩溃

### 重要理解
- 这是“**概率性有帮助的特征**”的典型表现
- 好特征 ≠ 决定性规则
- 好特征 = 在统计意义上提高预测成功的概率

---

## 七、我在这个实验中学到的核心经验

- 小数据下的高准确率需要保持警惕
- baseline 是解释模型表现的必要参照
- 单特征实验比直接堆模型更能暴露问题
- 训练集内打乱是识别数据泄漏的有效方法
- 判断特征是否有用，应关注**稳定行为**而不是某一次结果
